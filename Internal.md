# Internal thoughts for how this repository is supposed to work

The goal is to leave behind a technical manual that can be referenced without my assistance.

I need to be thinking about how this repository works from the perspective of someone who is accessing it for the first time.

The first thing they see is the README. What should it say? It should be a table of contents (TOC). Right now it's a few paragraphs from my milestone paper that introduces the project. That's fine to keep, but that should be a chapter of the TOC, not the first thing someone sees.

GitHub is a good platform for this because in theory this should also be a living document. Someone could fork this repository, make changes to it, and merge it back in with my approval. Will this actually happen? Probably not. But it would be good for the option to exist. Also, I can access the repository from any computer at any time, so there's no risk that I could lose it like a physical manual.

I should still produce a physical manual, but this repository will be the primary source that is updated.
